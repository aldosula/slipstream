# Slipstream Link Protocol, version 1 (SLP/1)

Normative spec for everything that crosses the wire between **Slipstream Wheel** (Android)
and **Slipstream Hub** (Windows). The reference implementation is
`tools/gen_test_vectors.py`; its output `docs/test-vectors.json` is binding. Where this text
and the script disagree, the script wins and this text is fixed.

All integers are **little-endian**. Offsets are in bytes from the start of the packet.

## 1. Design rules (why the protocol looks like this)

1. **State, not events.** Every INPUT packet carries the complete controller state. A lost
   packet costs nothing, because the next one (2 ms later) repeats everything.
2. **Discrete actions survive loss.** Gear shifts are not "button down / button up" events
   that a lost packet could swallow. They are wrapping **pulse counters** (u8). The hub
   compares counters and emits exactly the number of presses that happened, even if the
   packet that first carried the increment was lost.
3. **Newest wins.** Packets carry a u32 sequence number. The hub applies only packets newer
   than the last one it applied. Late or duplicate packets are dropped, never queued.
4. **Multipath for free.** The phone may send the *same bytes* over several transports
   (Wi-Fi UDP and USB at once). The hub applies whichever copy arrives first and drops the
   other as a duplicate. One path can stall and the wheel does not notice.
5. **Fixed size, no parsing.** INPUT is always 52 bytes, STATUS always 44. No varints, no
   JSON, no allocation on the hot path.
6. **Authenticated.** Every INPUT and STATUS packet ends in an 8 byte truncated HMAC-SHA256
   tag made from the pairing key, so no other device or app on the network can drive the car.

## 2. Pairing and keys

- A **pairing code** is 16 characters of the RFC 4648 base32 alphabet `A-Z2-7`
  (80 bits of entropy), generated by the hub from a CSPRNG. It is displayed grouped:
  `ABCD-EFGH-IJKL-MNOP`.
- **Normalization** of user input: uppercase; remove `-`, space and tab; map `0`->`O`,
  `1`->`I`, `8`->`B`; any other character outside the alphabet makes the code invalid;
  the result must be exactly 16 characters.
- `raw = base32decode(code)`, 10 bytes.
- `K = SHA256("slipstream/v1/key" || raw)`, 32 bytes. This is the HMAC key.
- `fingerprint = SHA256("slipstream/v1/fp" || K)[0..8)`, 8 bytes. Public; used in beacons so
  the phone can recognize *its* hub without revealing the key.
- `tag(body) = HMAC-SHA256(K, body)[0..8)`.
- Tags are compared in constant time.

QR payload shown by the hub:

```
slipstream://pair?v=1&code=ABCDEFGHIJKLMNOP&name=RACING-PC&port=47800&tcp=47802&host=192.168.1.20&host=10.0.0.4
```

`host` repeats once per usable IPv4 address of the PC. The code travels only in the QR and
on the hub screen, never over the network.

## 3. Ports

| Port | Proto | Direction | Use |
|---|---|---|---|
| 47800 | UDP | phone -> hub, hub -> phone | INPUT in, STATUS out (to the sender's address) |
| 47801 | UDP | hub -> broadcast | BEACON, once per second |
| 47802 | TCP | phone -> hub via `adb reverse` | USB link, framed INPUT in, framed STATUS out |

## 4. Common header (4 bytes)

| Off | Size | Field | Value |
|---|---|---|---|
| 0 | 1 | magic0 | `0x53` ('S') |
| 1 | 1 | magic1 | `0x4C` ('L') |
| 2 | 1 | version | `1` |
| 3 | 1 | type | `1` INPUT, `2` STATUS, `3` BEACON |

A receiver drops any packet whose magic, version, type or exact length is wrong.

## 5. INPUT (type 1, phone -> hub, exactly 52 bytes)

| Off | Size | Type | Field | Meaning |
|---|---|---|---|---|
| 0 | 4 | | header | type = 1 |
| 4 | 4 | u32 | epoch | Random non-zero value chosen when the phone's link starts. Changes on every app restart. |
| 8 | 4 | u32 | seq | Starts at 1, +1 per packet built. The same packet sent on two transports has the same seq. Wraps. |
| 12 | 4 | u32 | t_us | Phone monotonic clock in microseconds, low 32 bits, taken when the packet is built. |
| 16 | 2 | i16 | steer | -32767 full left .. 0 center .. +32767 full right. -32768 is never sent. |
| 18 | 2 | u16 | throttle | 0 released .. 65535 floored |
| 20 | 2 | u16 | brake | same scale |
| 22 | 2 | u16 | clutch | same scale |
| 24 | 2 | u16 | handbrake | same scale |
| 26 | 2 | u16 | aux | reserved, send 0, ignore on receive |
| 28 | 4 | u32 | buttons | Held-state bitmask. Bit i = held button i (0..23 used, 24..31 reserved, send 0). |
| 32 | 8 | u8[8] | pulses | Wrapping press counters. Channel 0 = shift up, 1 = shift down, 2..7 = user actions. |
| 40 | 1 | u8 | flags | bit0 `PAUSED` (phone not on the drive screen: hub outputs neutral), bit1 `CALIBRATING`, bit2 `MULTIPATH` (packet is being sent on more than one transport). Others 0. |
| 41 | 1 | u8 | reserved | 0 |
| 42 | 2 | u16 | rtt_100us | Phone's latest smoothed round-trip time in units of 100 us, saturating at 65535. 0 = unknown. Informational, for the hub display. |
| 44 | 8 | | tag | `tag(bytes[0..44))` |

## 6. STATUS (type 2, hub -> phone, exactly 44 bytes)

Sent by the hub at 20 Hz to every endpoint that delivered an accepted INPUT in the last
second (each UDP source address, each TCP connection).

| Off | Size | Type | Field | Meaning |
|---|---|---|---|---|
| 0 | 4 | | header | type = 2 |
| 4 | 4 | u32 | epoch | Epoch the hub is currently tracking |
| 8 | 4 | u32 | last_seq | Highest seq applied in that epoch |
| 12 | 4 | u32 | echo_t_us | The `t_us` of the packet `last_seq` |
| 16 | 4 | u32 | hold_us | Microseconds between the hub receiving `last_seq` and sending this STATUS |
| 20 | 4 | u32 | accepted | Distinct packets applied in this epoch (all transports together) |
| 24 | 4 | u32 | missing | Seq numbers skipped in this epoch (never arrived on any transport before a newer one) |
| 28 | 2 | u16 | rumble_strong | Force feedback / rumble from the game, 0..65535 |
| 30 | 2 | u16 | rumble_weak | same |
| 32 | 1 | u8 | output | low 7 bits: 0 none, 1 vJoy, 2 Xbox 360 (ViGEm). bit7 = output device error |
| 33 | 1 | u8 | hub_flags | reserved, 0 |
| 34 | 2 | u16 | reserved | 0 |
| 36 | 8 | | tag | `tag(bytes[0..36))` |

**RTT at the phone:** `rtt_us = (now_us - echo_t_us) - hold_us`, computed with u32 wrapping
subtraction. Only valid when `epoch` equals the phone's epoch. Smooth with an EWMA
(alpha = 1/8) for display; keep min and max over the last 5 s.
`hold_us` is not bounded by the STATUS period: on the slower path of a multipath link it can
exceed 1 s. It is always subtracted, so RTT stays correct. In multipath, STATUS goes out on
every live path but `echo_t_us` belongs to the copy that arrived first, so a path's figure is
"fastest path forward plus this path back". The phone shows the smallest live-path RTT.

**Loss at the phone:** `missing / (accepted + missing)` over the epoch, and also as a delta
between consecutive STATUS packets for a "last second" figure.

## 7. BEACON (type 3, hub -> UDP broadcast 47801, 17 + n bytes, unauthenticated)

| Off | Size | Type | Field |
|---|---|---|---|
| 0 | 4 | | header, type = 3 |
| 4 | 2 | u16 | udp_port (47800) |
| 6 | 2 | u16 | tcp_port (47802) |
| 8 | 8 | | fingerprint of the hub's current key |
| 16 | 1 | u8 | name_len n, 0..32 |
| 17 | n | | hub name, UTF-8 |

Sent once per second to `255.255.255.255` and to the directed broadcast address of every
up, non-loopback IPv4 interface (so USB tethering and Wi-Fi both see it). The phone uses the
beacon's **source IP** as the hub address. A phone that holds a key auto-connects only to a
beacon whose fingerprint matches.

## 8. TCP framing (USB link, port 47802)

Each message is `u16 length` followed by `length` bytes of one INPUT or STATUS packet.
Both ends set `TCP_NODELAY`. A frame whose length is not 52 (hub side) or 44 (phone side)
closes the connection. The hub listens on `127.0.0.1` only; the phone connects to
`127.0.0.1:47802`, which `adb reverse tcp:47802 tcp:47802` tunnels to the PC. The phone must
dial the IPv4 literal `127.0.0.1`; the platform loopback on Android is `::1`, which the tunnel
does not serve.

## 9. Receiver rules at the hub (normative)

1. Validate header and exact length, then the tag. Invalid packets are counted and dropped.
2. **Epoch.** If there is no current epoch, adopt the packet's epoch. If the packet's epoch
   differs from the current one, adopt it only if the current epoch has had no accepted
   packet for **300 ms**; otherwise drop it (two phones with the same key cannot fight).
   On adoption: reset `accepted`, `missing`, `last_seq`; take the packet's pulse counters as
   the baseline **without** emitting presses.
3. **Sequence.** Within the epoch, accept only if `seq_newer(seq, last_seq)`
   (serial-number arithmetic: `d = (seq - last_seq) mod 2^32`, newer iff `0 < d < 2^31`).
   If accepted and `d > 1`, `missing += d - 1`. Otherwise count a duplicate and drop.
4. **Pulses.** For each channel, `presses = (new - old) mod 256`; if `presses` is in
   `1..127` queue that many presses, else (0 or >= 128) queue none. Store `new`.
   A press is button down for `pulse_ms` (default 60 ms), then up for `gap_ms`
   (default 40 ms) before the next queued press on that channel.
5. **Apply immediately.** The accepted state is written to the virtual device on the
   receiving thread, before the next receive. No frame timer, no queue.
6. **Failsafe.** If no packet is accepted for `failsafe_ms` (default 200 ms), or the packet
   has `PAUSED`: throttle, brake, clutch, handbrake = 0, all held buttons released, queued
   pulses finish normally. Steering holds its last value on failsafe, and centers on `PAUSED`.
   When both apply (the last packet was `PAUSED` and the link then went silent), `PAUSED`
   wins: steering stays centered. Pulse increments carried by a `PAUSED` packet still count.

## 10. Output mapping (normative defaults)

vJoy device 1 (axes range 1..32768):

| Source | vJoy | Formula |
|---|---|---|
| steer | X | `1 + ((steer + 32767) * 32767 + 32767) div 65534` |
| throttle | Y | `1 + (p * 32767 + 32767) div 65535` |
| brake | Z | same |
| clutch | Rx | same |
| handbrake | Ry | same |
| pulse channel j (0..7) | button j + 1 | pulse |
| held bit i (0..23) | button i + 9 | held |

Xbox 360 (ViGEm):

| Source | X360 | Formula |
|---|---|---|
| steer | left thumb X | `steer` (i16) |
| throttle | right trigger | `p >> 8` |
| brake | left trigger | `p >> 8` |
| clutch | right thumb Y | `p >> 1` (as i16) |
| handbrake | A | held while `p >= 32768` |
| pulse 0 (shift up) | B | pulse |
| pulse 1 (shift down) | X | pulse |
| pulse 2..7 | RB, LB, Y, Back, Start, Right thumb | pulse |
| held bit 0..3 | D-pad up, down, left, right | held |

Each axis may be inverted in hub settings (`v' = 32769 - v` for vJoy).

Bluetooth HID mode (phone is the device, no hub): report ID 1, five 16-bit axes
(X steer as `steer + 32767` in 0..65534, Y throttle, Z brake, Rx clutch, Ry handbrake, each
0..65535), then 32 buttons with the same numbering as the vJoy table.

| Name | Value |
|---|---|

| Minimum spacing between INPUT packets | 1 ms |
| STATUS rate | 20 Hz |
| BEACON rate | 1 Hz |
| Epoch takeover silence | 300 ms |
| Failsafe | 200 ms |
| Pulse press / gap | 60 ms / 40 ms |
